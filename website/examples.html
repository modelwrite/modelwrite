Examples

Every model the repository ships, and honestly what the platform can do with each one.

sample/examples/ holds 98 files: five bundled example sets (96 model files from five upstream projects) and four more upstream examples that are fetched by a script because their licence or size keeps them out of the repository. This page is generated from sample/examples/README.md, so the licence table can never drift from what is actually committed. The state of each example — loadable, read-only, or refused — is stated, never overclaimed.

01 / The corpus

Every bundled example, with its licence and its honest state.

The four states below are the whole story. Loadable is XMI — the one format the platform imports and writes back today. Read-only (viewer) is SysML v2 textual, carried as Direction::ImportOnly: it imports, it does not write back. Large / refused is the one XMI export whose migration needs losses accepted by hand. Not importable is Gaphor’s own format, for which no binding exists. No bundled example is Loadable today: the only XMI in the bundle is the Thirty Meter Telescope, and it is refused pending acceptance — the one small loadable XMI, the MagicDraw coffee machine, lives in sample/corpus/ and is the showcase’s seeded coffee-machine project (see what loads today).

  • Loadable

    XMI. The platform imports it today and writes it back — a round-trip, not a screenshot.

  • Read-only · viewer

    SysML v2 textual. Carried by mw-binding-sysmlv2 as Direction::ImportOnly — it can be read, not written back.

  • Large · refused pending acceptance

    XMI (the loadable format), but 36 MB and its migration needs 48,553 losses accepted by hand before it loads.

  • Not importable

    Gaphor's own .gaphor XML, not OMG XMI. No Gaphor binding exists today, so the reader cannot open it.

02 / Loadable today

What the showcase can actually open.

The showcase seeds six projects, and one of them is a real imported vendor model: coffee-machine is the MagicDraw (CATIA Magic) SysML v1 corpus from sample/corpus/coffee-machine, carried through the XMI reader — 41 blocks, 25 requirements, 66 graph nodes, 95 graph edges, every loss named. The other five are hand-authored scenario models for the platform itself (the cafe-stand two-robot trade study included).

Why no further small XMI example was added

Adding another small, genuinely-imported XMI project to the showcase turns out to be impossible today — not for lack of trying, but because there is nothing new to import:

  • The MagicDraw corpus model is already seeded. coffee-machine is exactly that model, so it is already a real imported XMI project a visitor can click into.
  • The Gaphor coffee machine is not XMI. coffee-machine.gaphor is Gaphor’s own XML (<gaphor xmlns="https://gaphor.org/model">), not OMG XMI, and the engine has no Gaphor binding. It is bundled as corpus material, not forced into the showcase.
  • The Thirty Meter Telescope is refused. It is the one XMI in sample/examples/, and its migration needs 48,553 losses accepted by hand (362 blocks, 633 edges, round-trips exactly). It is not a small example.

Reproduce the loadable set

The seeded coffee-machine project is the OKF result of the XMI reader on the MagicDraw corpus. Reproduce the import and the round-trip:

cargo test -p mw-binding-xmi --test real_magicdraw -- --nocapture
cargo test -p mw-binding-xmi --test real_tmt -- --nocapture
cargo test -p mw-binding-sysmlv2 --test real_examples -- --nocapture

The seed is replayed from docs/deploy/seed-trial.mjs and the host manifest every hour; see docs/deploy/idc-1-trial.md.
