Modelwrite

The open source analytics platform for getting value from a SysML investment.

Your organisation has spent years building SysML models. Modelwrite is the open source analytics platform that shows what they are worth. It reads the models you already have, measures coverage, traceability and integration, tracks them baseline by baseline, and answers questions with the evidence attached. You keep your modelling tool.

01 / See it

Read the models you already have.

Modelwrite reads the SysML you already have. XMI and Cameo import carry a loss report that names what did not survive, so a loss is a decision you make rather than a surprise at acceptance. SysML v2 textual notation reads as a viewer: it imports, it does not write back. You keep your modelling tool.

The loss report, on a real model

Put a MagicDraw SysML export through the XMI reader and it reports what it carried and what it did not. On the coffee-machine MagicDraw model the reader carries 41 structure elements (the blocks), 25 requirements, and 66 graph nodes with 95 graph edges. It reports 252 blocking losses in total: 124 unmappable content losses and 128 lossy drops, every one named.

Reproduce it:

cargo test -p mw-binding-xmi --test real_magicdraw -- --nocapture

SysML v2 textual, as a viewer

The engine reads a stated subset of SysML v2 textual notation. It imports and does not export, so a SysML v2 model cannot be written back. Reproduce it:

cargo test -p mw-binding-sysmlv2 --test real_examples -- --nocapture

02 / Measure it

Coverage, traceability, integration. The graph gaps lead.

Coverage names which requirements are satisfied, refined, verified or allocated. Traceability names the edges between them. Integration asks whether the model is one connected whole. The graph gaps expose the model nobody can see at a glance.

  • 1

    Orphaned items. A node with no edge. It is present, but nothing connects to it.

  • 2

    Isolated groups. More than one connected component. The model is split.

  • 3

    Dangling links. An edge whose endpoint is missing. The link points at nothing.

Each gap is named, not summarised into a score, and trended baseline by baseline so drift is visible when a baseline changes. These are the metrics in the analytics schema, listed in the analytics section.

03 / Ask it

Ask the model questions, with the evidence attached.

Agents and the MCP surface ask questions of the model, and every answer carries its basis: the element, the edge and the run that produced it. An agent reads and proposes. It cannot write. Only a human with the write role accepts a proposal into a commit, and the commit records both parties.

04 / Trust it

05 / Analytics

Every metric, from the engine.

This list is generated from spec/analytics/metric_definitions.json, the authoritative schema produced by the engine. It is not maintained by hand. The schema is Apache-2.0, so anyone can build a connector.

  • Graph nodes

    graph.node_count active

    Number of nodes in the graph section (every element as a node).

    depends on graph.nodes

  • Graph edges

    graph.edge_count active

    Number of edges in the graph section (every relationship as an edge).

    depends on graph.edges

  • Orphaned elements

    graph.isolated_count active

    Number of graph nodes with no incident edge. The graph-gaps headline: every orphan is named in graph_stats.isolated.

    depends on graph.nodes, graph.edges

  • Isolated groups

    graph.component_count active

    Number of connected components in the graph. More than one means the model is split into isolated groups.

    depends on graph.nodes, graph.edges

  • Requirements total

    coverage.total active

    Number of requirements in the model.

    depends on requirements

  • Satisfied links

    coverage.satisfied active

    Number of dependency edges labelled Satisfy that target a requirement.

    depends on graph.edges

  • Refined links

    coverage.refined active

    Number of dependency edges labelled Refine that target a requirement.

    depends on graph.edges

  • Verified links

    coverage.verified active

    Number of dependency edges labelled Verify that target a requirement.

    depends on graph.edges

  • Allocated links

    coverage.allocated active

    Number of dependency edges labelled Allocate with a requirement endpoint.

    depends on graph.edges

  • Covered requirements

    coverage.covered active

    Number of requirements covered by at least one Satisfy/Refine/Verify/Allocate edge.

    depends on requirements, graph.edges

  • Uncovered requirements

    coverage.uncovered active

    Number of requirements with no covering edge. Each is named in the coverage report's uncovered list.

    depends on requirements, graph.edges

  • Specification size

    compliance.specification_size active

    Number of requirements in the caller's specification (the portfolio question).

    depends on requirements

  • Specification covered

    compliance.covered_count active

    Requirements of the specification present and covered by the model.

    depends on requirements, graph.edges

  • Specification uncovered

    compliance.uncovered_count active

    Requirements of the specification present in the model but uncovered.

    depends on requirements, graph.edges

  • Specification unknown

    compliance.unknown_count active

    Requirements of the specification absent from the model entirely. Never rendered as a blank.

    depends on requirements

  • Costed requirements

    cost.costed_count active

    Number of requirements with at least one cost record across the supplied datasets.

    depends on requirements, dataset

  • Uncosted requirements

    cost.uncosted_count active

    Number of requirements with no cost record. Never rendered as zero.

    depends on requirements, dataset

  • Gate passed

    gate.passed active

    Whether the gate run passed (1) or failed (0) against its reference.

    depends on gate

  • Validation errors

    gate.validation_errors active

    Number of validation errors the gate recorded for the candidate.

    depends on gate, validate

  • Validation warnings

    gate.validation_warnings active

    Number of validation warnings the gate recorded, including dangling edge endpoints.

    depends on gate, validate

  • Missing elements

    gate.roundtrip.missing_elements active

    Elements present in the reference but missing from the candidate after a round trip.

    depends on gate, diff

  • Extra elements

    gate.roundtrip.extra_elements active

    Elements present in the candidate but not the reference after a round trip.

    depends on gate, diff

  • Missing edges

    gate.roundtrip.missing_edges active

    Edges present in the reference but missing from the candidate after a round trip.

    depends on gate, diff

  • Extra edges

    gate.roundtrip.extra_edges active

    Edges present in the candidate but not the reference after a round trip.

    depends on gate, diff

  • Changed attributes

    gate.roundtrip.changed_attributes active

    Attributes whose value differs between reference and candidate after a round trip.

    depends on gate, diff

06 / Limits

What it does not do

Each of these is a limit of the current release, and each one is checkable from the repository. This section is the reason the rest of the page is believable.

  • x

    An agent cannot write.

    It proposes. Only a human with the write role accepts a proposal into a commit, and the resulting commit records both parties. An agent token cannot hold a write or admin role.

  • x

    There is no numeric or physical simulation.

    Model-level analysis and simulation are supported: coverage, traceability, composition and process. FEA, thermal and fluid solvers are not part of this platform and are not planned. Modelwrite reasons about the model, not about the physics.

  • x

    Real vendor migration is not complete.

    On the MagicDraw coffee-machine corpus the reader reports 252 blocking losses. A 36 MB Cameo export, the Thirty Meter Telescope model, carries 362 blocks and 633 edges, round-trips exactly, and reports 45,725 named losses for the constructs it does not carry. Named rather than dropped in silence. SysML v2 textual notation is carried as a viewer: it reads, it does not write back.

    Reproduce the two measurements:

    cargo test -p mw-binding-xmi --test real_magicdraw -- --nocapture
cargo test -p mw-binding-xmi --test real_tmt -- --nocapture
  • x

    The native XMI-to-OKF direction is not independently measured.

    The gate measures the binding's own OKF-to-XMI-to-OKF round trip. The read rests on the binding's self-reported loss report, not on an independent golden corpus.

  • x

    There is no CAD or geometry authoring.

    Modelwrite integrates with CAD rather than replacing it. The 3D side of the CATIA portfolio is out of scope by design, and so is becoming a general-purpose drawing tool.

07 / FAQ

Does it replace my modelling tool?

No. Modelwrite reads and does not write. It imports from your modelling tool, measures what is there, and reports what it could not carry. You keep your modelling tool.

  • Does an AI change my model?

    It proposes. A human accepts. An agent cannot write: only a human with the write role accepts a proposal into a commit, and the commit records both parties.

  • What does it cost, and what licence?

    The code is free and open source. The engine and server are AGPL-3.0-or-later. The interchange format, the importers and the exporters are Apache-2.0. See the licence section.

08 / Install

Install and run it yourself

The Rust crates are not published to crates.io; build from the repository. You need Rust stable via rustup.

Build and test

cargo build --workspace
cargo test --workspace

Run the gate on the corpus

Expected output: GATE PASS.

cargo run -p mw-gate -- --reference sample/corpus/coffee-machine/okf/expected/coffee_machine_model.json --candidate sample/corpus/coffee-machine/okf/expected/coffee_machine_model.json

Deploy it

As a container, a Compose trial on one machine, or a Helm release.

docker build -f deploy/Dockerfile -t modelwrite/modelwrite:0.1.0 .
docker compose -f deploy/docker-compose.yml up --build
helm install modelwrite deploy/helm/modelwrite

The service runs in open mode unless you configure authentication.

Open mode means an anonymous admin. The image refuses to start that way unless MW_ALLOW_OPEN=yes is set, so for anything shared, set MW_AUTH_TOKEN or MW_AUTH_JWKS instead. The Helm chart does not do TLS, backups or high availability; see deploy/README.md for what it leaves to you.

09 / Architecture

Architecture

The engine crates are the contract. The server, the CLI and every connector build on them, and nothing bypasses the OKF crate and the gate.

Clients

  • Web workbench: server-rendered HTML and inline SVG
  • mw command line and the CI runner
  • MCP clients and AI agents
  • REST integrations

mw-serverAGPL-3.0-or-later

  • HTTP API and the workbench UI
  • Commits and branches · three-way merge · locks as leases · audit log
  • Identity and roles · gate · migration · agent proposals and acceptance
  • Governance · analytics
  • Storage: SQLite for one user, PostgreSQL for a team

Engine cratesAGPL-3.0-or-later

  • okf · graph · gate · binding · binding-xmi (the SysML v1 XMI reader) · binding-sysmlv2 (the SysML v2 textual viewer)
  • agent (Reasoner and proposals) · capi (C ABI) · mcp (MCP server) · analytics

InterchangeApache-2.0

  • OKF 1.0 format and schema

Deployment

  • Docker image · Docker Compose trial · Helm chart · air-gapped bundle
